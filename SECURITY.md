# Security Policy

TravelsTREM takes the security of its platform, users, travel partners, agencies, and associated services seriously. We appreciate responsible security research and encourage the reporting of potential vulnerabilities so they can be investigated and resolved appropriately.

## Supported Versions

TravelsTREM is continuously developed and updated. Security fixes are generally applied to the current production version of the platform.

| Version                     | Supported |
| --------------------------- | --------- |
| Current production version  | ✅        |
| Current development version | ✅        |
| Older/deprecated versions   | ❌        |

Older or deprecated releases may no longer receive security patches. Users and deployment environments should use the latest supported version wherever possible.

## Reporting a Vulnerability

If you discover a potential security vulnerability affecting TravelsTREM, please report it responsibly instead of publicly disclosing the issue.

When submitting a vulnerability report, please include:

- A clear description of the vulnerability.
- The affected TravelsTREM product, service, page, API, or endpoint.
- Steps required to reproduce the issue.
- Screenshots, logs, proof-of-concept code, or other supporting information where relevant.
- The potential security impact.
- Any suggested mitigation, if available.

Please avoid including unnecessary personal information, customer data, authentication credentials, or other sensitive information in your report.

## What to Expect

After receiving a vulnerability report, TravelsTREM will aim to:

1. Acknowledge receipt of the report within **3 business days**.
2. Review and validate the reported vulnerability.
3. Request additional information if required to reproduce the issue.
4. Determine the severity, potential impact, and appropriate remediation.
5. Provide reasonable progress updates while the issue is being investigated.
6. Notify the reporter when the vulnerability has been resolved or when a decision has been made regarding the report.

Resolution timelines may vary depending on the complexity, severity, affected systems, third-party dependencies, and operational impact of the vulnerability.

## Responsible Disclosure

We ask security researchers to provide TravelsTREM with reasonable time to investigate and resolve a vulnerability before publicly disclosing it.

Please do not:

- Publicly disclose an unresolved vulnerability.
- Access, modify, download, or delete data belonging to other users.
- Perform denial-of-service or resource-exhaustion testing.
- Use automated testing that significantly impacts platform availability.
- Attempt social engineering, phishing, or physical attacks against TravelsTREM employees, partners, agencies, or users.
- Attempt to obtain passwords, OTPs, payment credentials, API secrets, or other user credentials.
- Exploit a vulnerability beyond what is reasonably necessary to demonstrate its existence.
- Disrupt TravelsTREM services or the services of third-party providers used by the platform.

Security testing should only be performed against systems and accounts that you are authorized to access.

## Third-Party Services

TravelsTREM may integrate with third-party services such as payment gateways, authentication providers, travel inventory providers, airlines, hotels, APIs, communication providers, or other technology partners.

Vulnerabilities that exist exclusively within a third-party service should generally be reported directly to that provider. However, if a third-party vulnerability creates a security risk specifically within TravelsTREM's implementation or integration, you may report it to us as well.

## Vulnerability Acceptance

A reported vulnerability may be accepted when it presents a reproducible and meaningful security risk to TravelsTREM, its users, partners, infrastructure, or data.

A report may be declined when it:

- Cannot be reproduced.
- Does not demonstrate a meaningful security impact.
- Relates exclusively to an unsupported or deprecated version.
- Concerns functionality operating as intended without a security impact.
- Is based solely on automated scanner output without demonstrating exploitability.
- Relates exclusively to a third-party system outside TravelsTREM's control.
- Requires unrealistic or already-compromised conditions to exploit.

When practical, we will explain why a submitted report has been accepted or declined.

## Bug Bounty

Unless TravelsTREM explicitly announces a bug bounty or security rewards program, reporting a vulnerability does **not** guarantee financial compensation, rewards, or other benefits.

Responsible vulnerability reports are nevertheless appreciated and help us improve the security of the TravelsTREM ecosystem.

## Good-Faith Security Research

TravelsTREM supports responsible, good-faith security research conducted in accordance with this policy.

Researchers who identify vulnerabilities should make reasonable efforts to:

- Minimize privacy risks.
- Avoid accessing unnecessary data.
- Avoid service disruption.
- Stop testing if sensitive customer or partner information becomes accessible.
- Report the vulnerability promptly and confidentially.
